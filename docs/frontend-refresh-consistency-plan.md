# 前端日历刷新一致性计划

## 背景

当前前端同时维护个人日历 `events`、团队日历 `teamEvents`、团队详情和事件详情等多份本地状态。部分操作只刷新了其中一份状态，导致后端已经变更后，另一个视图仍显示旧数据。

已观察到的问题：

- 在个人日历打开团队事件并删除后，团队日历中事件消失，但个人日历仍保留旧柱状体。
- 后端查询确认该事件已经 `deleted_at`，个人日历接口也不再返回，残留来自前端本地 `events`。

## 核心原则

只要查看某个团队的事件，无论是新团队还是旧团队，都应该刷新该团队日历，并同步刷新个人日历。

原因：

- 团队事件可能影响个人日历中的 `pending`、`joined`、`left` 状态。
- 团队事件可能被其他成员移动、改名或删除。
- 个人日历中展示的团队事件和团队日历来自同一后端事实源，不应长期保留两套不同快照。
- 当前没有 websocket、轮询或增量同步，因此进入团队视图时刷新是最简单可靠的一致性边界。

## 计划改动

新增统一刷新方法，例如：

```ts
async refreshEventViews(teamId?: string) {
  await this.loadCalendarEvents()
  if (teamId) await this.loadTeamEvents(teamId)
}
```

需要在以下场景使用：

- 进入任意团队详情页时：
  - 刷新团队成员和团队日历。
  - 同步刷新个人日历。
- 已选中某团队时切回 Team tab：
  - 刷新当前团队日历。
  - 同步刷新个人日历。
- 团队事件删除成功后：
  - 关闭事件详情。
  - 刷新当前团队日历。
  - 同步刷新个人日历。
- 团队事件移动成功后：
  - 刷新当前团队日历。
  - 同步刷新个人日历。
- 团队事件标题编辑成功后：
  - 刷新当前团队日历。
  - 同步刷新个人日历。
- 加入或退出团队事件成功后：
  - 刷新当前团队日历。
  - 同步刷新个人日历。
- 接受或拒绝 pending 团队事件成功后：
  - 刷新个人日历。
  - 如果当前正在查看对应团队，刷新该团队日历。
- 退出团队成功后：
  - 刷新团队列表。
  - 同步刷新个人日历。
  - 如果退出的是当前选中团队，清空当前团队详情和团队日历。

筛选“只显示本 Team 活动”只影响团队视图过滤，不需要刷新个人日历。

## 验收场景

- 在团队页创建团队事件后，个人日历立即显示对应团队事件。
- 在个人日历打开已加入团队事件并删除后，个人日历和团队日历都不再显示该事件。
- 在团队日历移动团队事件后，个人日历中该事件日期同步变化。
- 在团队日历修改团队事件标题后，个人日历中该事件标题同步变化。
- 在团队日历加入团队事件后，个人日历显示该事件为已加入状态。
- 在团队日历退出团队事件后，个人日历不再显示该事件或显示符合后端状态的结果。
- 进入任意旧团队详情页时，如果后台数据已变化，团队日历和个人日历都更新到最新状态。
- 退出团队后，个人日历不再残留该团队事件。

## 后续优化

当前方案以明确刷新换取状态一致性。若后续数据量变大，可以再考虑：

- 按团队或用户维护 `updated_at` 版本号，未变化时跳过全量刷新。
- 对日历接口做增量同步。
- 增加页面 `onShow` 的节流刷新。
- 使用 websocket 或服务端事件推送团队事件变更。
